- 정적 팩토리 메셔드
정적 팩토리 메서드 패턴은 생성자를 통한 객체 호출이 아니라 static method를 통해 간접적으로 생성자를 호출하는 객체를 생성하는 방식이다.
of나 from getInstance 등을 통해 메서드 네이밍을 함.
public static Car nameOf(String name){
    return new Car(name)
}
이런 방식으로 static 메서드를 통해 객체를 생성하는 것이다.
- 장점
생성 목적에 대해서 nameOf 같은 이름 표현이 가능하고 getInstance 메서드를 사용해 오로지 하나의 객체만 반환하도록 하는 싱글톤 디자인 패턴을 구상할 수도 있다.
  class Singleton {
  private static Singleton instance;

  private Singleton() {}
  public static synchronized Singleton getInstance() {
  if (instance == null) {
  instance = new Singleton();
  }
  return instance;
  }
  }

  하위 자료형 객체 반환 가능 스마트폰 클래스가 있다면 스마트폰 인터페이스를 구현하는 여러 개의 객체 중 public static을 통해 원하는 객체 반환 가능
  비슷하게 인자에 따라서 다른 객체를 반환하도록 할 수 있다.

- 빌더 패턴

빌더 패턴은 어떤 객체의 멤버에 대해 setter 형식으로 지정해주고 마지막에 build 해주는 방식이다.
생성자 매개변수가 많아질수록 순서가 헷갈릴 수 있는데 빌더패턴을 사용하면 일관성있게 생성할 수 있다.
객체 생성을 주도적으로 해서 생성 단계 지연 가능
필수 멤버와 선택적 멤버를 분리 가능하다.

이펙티브 자바 빌더 패턴과 goF의 빌더 패턴이 있는데 이펙티브 자바는 지정해야 할 인자가 많을 때, 객체의 일관성 불변성이 목적이고 goF의 빌더 패턴은 객체의 생성 단계 순서를 결정해두고 각 단계를 다양하게 구현하고 싶을 때 사용한다.
이펙티브 자바 빌더 패턴은 builder 패턴을 사용할 객체의 내부에 정적 클래스 Builder를 구현하는 방식이다.
이 때 하나의 빌더 클래스는 하나의 객체 생성만을 위해 사용되고 대상 객체는 빌더 객체에 의해 초기화된다.
static으로 선언해주는 이유는 일반 내부 클래스로 구현한다면 내부 클래스를 생성하기 전에 외부 클래스를 생성해야줘야 하기 때문이고 메모리 누수 문제 때문에 static으로 선언해준다.



빌더 패턴을 사용했을 때 필드를 builder 를 직접 참조하게 하면 builder 값이 변경 되면 객체의 필드 값도 바뀌기 때문에 방어적 복사를 해야함.
getLottos 에서 방어적 복사를 했어도 반환한 후에 리스트를 수정할 수 있기 때문에 외부에서 변경 불가능하도록 해야함
get을 할 때마다 새로운 객체들 만들어주거나 불변 객체로 만들면 해결 가능

lottos 의 빌더에서 가격 검증을 실행했지만 따로 클래스를 만들어서 관리를 하기 때문에 상관없다고 생각을 했습니다.

정적 팩토리 메서드는 객체의 필드를 알아보기 쉽게 정의해서 바로 만들 수 있지만 많이 사용하면 메모리가 낭비될 것 같다.
